Protocolo OPEN KEY — Autenticación Soberana
Cada request al Daemon Go atraviesa 3 Guards antes de acceder a Ollama
1
Guard 1 — Interceptación Stateless & Extracción de Prefijo
El Daemon captura el header X-AURA-KEY en cada request. Si la llave mide menos de 16 caracteres → rebota con HTTP 401 sin consultar BD. Se extrae el Key Prefix (primeros 16 chars) para indexación veloz.
if len(key) < 16 { return 401 }
2
Guard 2 — Resolución Indexada en PostgreSQL
Go ejecuta un query rápido buscando el prefix en acadep_core_tokens_ledger. Si el proyecto no existe, está suspendido o sin CAPEX → rebota inmediatamente. Evita calcular hashes bcrypt para llaves inválidas (protección CPU).
SELECT * FROM ledger WHERE key_prefix = $1 AND status = 'active'
3
Guard 3 — Validación Criptográfica Bcrypt cost:12
Solo si los Guards 1 y 2 pasan: el motor ejecuta el match matemático asíncrono. Compara la llave en texto plano (X-AURA-KEY) contra el hash bcrypt almacenado en PostgreSQL. Al validar → abre el canal hacia Ollama y descuenta tokens del CAPEX.
bcrypt.CompareHashAndPassword(storedHash, []byte(presentedKey))

Grandes Victorias — Problemas Históricos Vencidos
4 errores críticos resueltos en esta sesión de arquitectura
🔌
Error de Adaptador Comercial Bloqueando ACADEP
La función classifyApiError() mostraba "Sin adaptador activo" para ACADEP. Resuelto añadiendo el parámetro providerName con guardia explícita: prov !== 'acadep' en el clasificador de errores del modal de diagnóstico.
✓ Resuelto
🗄️
Colapso del Bridge 404 — Dependencia de BD Eliminada
testAcadepConnection() buscaba el proveedor en ai_settings (BD). Decoupling total: ahora lee exclusivamente desde config('services.acadep.*') mapeado al .env del servidor. Cero consultas SQL en el handshake.
✓ Resuelto
⏱️
Spinner Infinito Bloqueando la UX
La clase CSS .acadep-spinner tenía mayor especificidad que .hidden. Resuelto con la función resetHandshakeBtn() usando style.display='none' directo — vence toda especificidad CSS sin excepción en ambos .then() y .catch().
✓ Resuelto
🔐
Desalineación Criptográfica 401 — Hash Bcrypt Sincronizado
El Daemon Go retornaba HTTP 401 porque open_key_hash en PostgreSQL no correspondía a ACADEP_AURA_KEY. Resuelto con el endpoint POST /acadep/generate-query que genera password_hash($key, PASSWORD_BCRYPT, ['cost'=>12]) y entrega el SQL listo.
⚡ Handshake SUCCESS
